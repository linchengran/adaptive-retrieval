## 2. 路由器选型过程（M2 的科学核心，含一次有价值的失败）

### 2.1 被否决的方案：余弦置信间隔路由

最初的假设：dense 检索的分数间隔（top1-top2 或 top1-top5）大 → 排名已稳定 → 可免 rerank。

在 17 条 dev 集上该方案"表现完美"（15/17 走快路径、hit@1 反超全量 rerank、延迟降 5.6 倍），**但换到 72 条 train 集立即失效**：θ=0.05 时 hit@1 掉到 0.764（超过容忍度），θ=0.08 时 71/72 查询被迫走慢路径。

区分度检验给出了判决性证据：正确 top1 与错误 top1 的间隔中位数为 **0.0105 vs 0.0086（m12）/ 0.0403 vs 0.0346（m15）**，两组分布几乎重合。**结论：在小语料、归一化余弦下，分数间隔对"rerank 是否有必要"没有预测力。** 这条负结果已写入 `router.json` 的 `signal_reports`，避免后续重走弯路。

*教训记录：dev 集只有 17 条且偏简单，曾产生严重乐观的假象；选型集必须足够大且覆盖真实查询分布。*

### 2.2 采用的方案：稠密-关键词一致性路由

新信号：dense 与 BM25 的 top1 是否一致（BM25 打分仅 ~0.25ms，几乎零成本）。

train 集验证：一致组占 27.8%，其中 dense top1 正确率 **0.900**（先验仅 0.569）。两路独立机制给出一致答案时，排名大概率已稳，rerank 是纯浪费；不一致时升级为 dense 召回 + rerank。

## 3. 测试集 v2 五臂结果（55 条，chunk 级）

| 检索臂 | hit@1 | hit@5 | recall@5 | ndcg@5 | 平均延迟 |
|--------|-------|-------|----------|--------|---------|
| bm25 | 0.400 | **0.855** | 0.845 | 0.639 | 0.26 ms |
| dense | 0.418 | 0.618 | 0.609 | 0.526 | 9.9 ms |
| hybrid_rrf | 0.436 | 0.764 | 0.745 | 0.602 | 11.3 ms |
| **dense+rerank** | **0.655** | 0.782 | 0.764 | 0.705 | 130.1 ms |
| **routed(agreement)** | 0.636 | 0.782 | **0.773** | **0.705** | **103.8 ms** |

### 核心发现

**发现 1：一致性路由实现了"rerank 级精度、便宜 20%"。**
routed 相比全量 rerank：hit@1 −0.018（在 0.02 容忍度内），ndcg@5 与 recall@5 持平甚至略优；平均延迟 130.1→103.8 ms（**−20%**）。测试集上快路径占 29%（16/55），与 train 选型时的 27.8% 高度一致——**信号泛化成功了**，这正是当初 margin 方案做不到的。

**发现 2：混合检索的最大收益在排序深度而非首位。**
hybrid 相比 dense：hit@1 仅 +0.018，但 hit@5 从 0.618 → 0.764（+0.145）、ndcg@5 +0.077，代价只有 +1.4 ms。融合召回把"答案在库里但排不进前 5"的查询捞了回来——这对"召回给 rerank 喂料"的管线结构意义更大（M3 的 hybrid+rerank 臂将直接验证）。

**发现 3：BM25 的深度优势被证实。**
纯 BM25 拿到了所有臂中最高的 hit@5（0.855）。29 个 chunk 的小语料中关键词匹配的覆盖能力被低估了——这进一步支持"短路径不该是纯 dense，而应该是混合"的 M3 设计。

**发现 4：v2 测试集有效提升了难度。**
dense hit@1 从 v1 的 0.647 降到 v2 的 0.418，各臂差距拉开（此前 hit@5 已 0.94 无区分度），后续实验的分辨率显著改善。

## 4. 路由分析

| 指标 | train（选型集） | test v2 |
|------|----------------|---------|
| 快路径占比 | 27.8% | 29.1% (16/55) |
| 快路径正确率 | 0.900 | —（见 per_query） |
| 全臂 hit@1 损失 | — | −0.018 |

延迟结构：快路径 ~10 ms，慢路径 ~137 ms（含 BM25 开销），期望延迟 = 0.29×10 + 0.71×137 ≈ 100 ms，与实测 103.8 ms 吻合。**当前 20% 的节省上限由快路径占比决定**：一致性是二值且保守的信号，要进一步提高占比需要更强的路由特征（M3 学习型路由器）或改变慢路径本身（见下）。

## 5. 过程中发现并修复的问题

1. **RRF 融合去重 bug**：dense 与 bm25 臂各自加载 chunks 列表，同一逻辑 chunk 是不同 Python 对象，用 `id()` 去重失效导致结果含重复项（recall@5 曾出现 1.15 > 1 的异常）。已改为按 `chunk_id` 去重。教训：融合层的去重键必须是逻辑 ID，不能是对象标识。
2. **单臂跑分覆盖结果文件**：`--only` 模式下后跑的臂会覆盖整个 results.json，多臂结果必须一次全量跑或改用增量合并。
3. **测试集溯源标记失准**：凭记忆并入的 held-out 条目只有 10/17 与原文件逐字一致，已重标为 `paraphrase_v2` 并在文件描述中如实说明。

## 6. 效度威胁

1. 测试集 55 条仍偏小；±1 条查询 = ±0.018 指标波动，routed 的 −0.018 恰在噪声边缘，结论表述为"精度持平"而非"有损/无损"。
2. 语料仍为 29 个 chunk；BM25 的强 hit@5 可能是高重叠小语料的特有现象，扩语料后需复验。
3. 一致性路由的快路径正确率（train 0.90）依赖"两路错误独立"的假设，若 BM25 与 dense 的错误分布相关（同受分块质量影响），信号强度会在别的语料上漂移。
4. 延迟为 GPU 环境数字；生产 CPU 环境 rerank 成本占比更高，路由的相对收益预期更大，但绝对数字需在线上复测。

## 7. M3 就绪状态与下一步

1. **hybrid+rerank 臂**：用混合召回（hit@5 已 0.764）喂 rerank，预期 hit@1 突破 0.655；
2. **学习型路由器**：特征候选——一致性、查询长度/实体密度、BM25 最高分、dense 分数熵；标签 = "rerank 是否改变/修正 top1"（可从 train 集自动构造）；
3. **检索自评兜底**：慢路径结果置信度仍不足时的最后一道闸（需接 LLM，成本另算）；
4. **分层分块**：针对 v2 中仍双双落空的查询（原文表述与问题差异最大的部分）；
5. 语料与测试集继续扩充（30+ chunk、100+ 查询是 M3 目标）。
