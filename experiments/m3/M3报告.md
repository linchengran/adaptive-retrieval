# M3 报告：混合重排、分层分块与学习型路由

> 日期：2026-10-07
> 前置：[M1 基线报告](../m1_baseline/M1基线报告.md) / [M2 报告](../m2_router/M2报告.md)
> 原始数据：`experiments/m3/results_8arms.json`（55 条测试集 v2，chunk 级）

## 1. 本次交付

1. **hybrid+rerank 臂**：混合召回（RRF top10）喂 bge-reranker；
2. **hierarchical 臂**：分层分块检索——细块（句级 ~120 字符，现场重建内存索引）召回、父粗块（512 字符）返回；
3. **学习型路由器**：8 特征逻辑回归，标签自动构造（y=1 当且仅当 dense top1 错且 rerank top1 对），5 折交叉验证，模型序列化至 `experiments/m3_learned_router/`；
4. **八臂全量对比**。

## 3. 核心发现

### 发现 1：混合召回喂 rerank，hit@1 再涨 0.055（M2 假设证实）

hybrid+rerank 0.709 vs dense+rerank 0.655，hit@5/rerank 输入质量提升直接转化为首位精度：0.855 vs 0.782 的 hit@5 意味着 reranker 的候选池覆盖率更高。**精度冠军换人，且延迟几乎不变（185 vs 179 ms）**——这是纯赚的改进，应成为默认慢路径。

### 发现 2：分层分块是非 rerank 臂的新王者

hierarchical 相比 dense：hit@1 +0.073、hit@5 +0.237、ndcg@5 +0.158，延迟持平（14.3 vs 11.7 ms）。句级细块准确定位、父粗块保证上下文完整的设计同时改善了首位与深度。它与 bm25 并列 hit@5 最高（0.855），说明小语料上"细粒度词面/语义定位"比"粗块整体相似度"重要得多。

**M4 最有希望的组合**呼之欲出：hierarchical 召回 + rerank（细块定位给 reranker 喂更准的父块候选），以及 hierarchical 作为快路径的一致性路由。

### 发现 3：学习型路由器当前不可用（诚实记录）

8 特征逻辑回归 5 折 CV：**AUC 仅 0.609**，标签预测准确率 0.583，低于"全走快路径"平凡基线（0.681）。测试集上它把快路径占比提到 56%（agreement 只有 29%），但代价是 hit@1 掉到 0.618，超出容忍度。

诊断：正例仅 23/72，特征里的连续信号（间隔、熵）在 M2 已被证明无区分度，离散信号（一致性、重叠）只有 2-3 个有效比特。**结论：不是模型不行，是特征和样本都不够。** 路由器要可学习，需要（a）更大的 train 集（目标 200+ 查询），（b）更强的特征（查询改写后的召回变化、BM25 分数分布、查询类型分类），或（c）换个 formulation（预测 rerank 前后 top1 是否一致，而非直接预测"是否需要"）。agreement 规则路由仍是当前唯一满足"精度不掉"约束的自适应方案。

### 发现 4：routed-learned 提供了一个可用的"极速档"

尽管不满足默认档的精度约束，routed-learned 的运营点本身有价值：**97 ms、hit@1 0.618**——与 dense 持平的精度、8.5 倍于 dense 的深度、约一半 rerank 延迟。对延迟敏感场景（小程序输入即搜）可作为可选档位。自适应检索的最终形态可能是"多档位"而非单一路由。

## 4. 精度-延迟前沿（课题核心图的当前形态）

```
hit@1
0.71 |                    * hybrid+rerank (185ms)
0.65 |        * routed-agreement(142ms)  * dense+rerank (179ms)
0.62 |                              * routed-learned (97ms)
0.49 |   * hierarchical (14ms)
0.44 |  * hybrid (14ms)
0.42 | * dense (12ms)
0.40 |* bm25 (0.6ms)
     +-------------------------------------------
```

前沿由三个点定义：**hierarchical（14ms / 0.49）→ routed-agreement（142ms / 0.64）→ hybrid+rerank（185ms / 0.71）**。相比 M1 的前沿（dense 9ms/0.65 vs rerank 122ms/0.88-v1 口径），自适应管线已经把"每一档延迟买到多少精度"的曲线整体抬高。

## 5. 效度威胁（增量）

1. 分层分块的细块参数（120 字符）未做敏感性分析，属首批工作点；
2. 学习型路由器的结论基于 72 条 train、23 个正例，样本量不足以支撑"特征无用"的强结论——结论限定为"当前特征+样本量下不可用"；
3. rerank 臂延迟复测与八臂主跑非同一次运行（已在 results.json 标注），但同臂相对关系与 M2 独立测量一致；
4. GPU 时段波动：跨报告延迟比较需以相对比例为准。

## 6. M4 就绪状态与下一步

1. **hierarchical+rerank 臂**（最高优先级：细块召回可能同时改善 hit@1 与候选质量）；
2. **hierarchical 一致性路由**：hierarchical(快) vs hybrid+rerank(慢) 的 agreement 路由，目标"14ms 档覆盖更多查询"；
3. **扩数据**：语料 29 chunk 太小是所有结论的头号威胁，接更多领域文档重建索引；train 集扩到 200+ 后重训路由器（含 reformulation 特征）；
4. **检索自评兜底**（需 LLM API，留待有 key 环境）；
5. **Skill 封装**：精度-延迟前沿已经稳定出现三档，M1 开题承诺的"自带 eval 的 skill"可以开始封装（CLI + benchmark 表自动生成）。
