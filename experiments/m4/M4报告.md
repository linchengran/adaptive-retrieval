## 3. 核心发现

### 发现 1：hier+rerank 刷新排序质量上限

hit@5 从 0.855 → **0.927**，hit@3 → 0.818，ndcg@5 → 0.805，全部全场第一；hit@1 与 hybrid+rerank 并列 0.709。细块召回给 reranker 提供的父块候选（recall@5 0.909）质量显著高于混合召回（0.845）。对 RAG 场景更重要的是 top3/top5 的深度：喂给生成模型的 5 段上下文里有 4.6 段含答案。

### 发现 2：routed-hier 用 92ms 拿到冠军级 hit@1

分层版一致性路由：hit@1 0.709（与 best 档并列第一）、延迟 91.5ms（比 best 档省 22%）、快路径占比 31%。它是"精度不设防"意义上的最优点：**不付出任何 hit@1 代价即可省下约 1/4 延迟**。代价在深度档（hit@5 0.836 vs 0.927），路由保守升级换来的。

### 发现 3：三档前沿已经稳定，可以封装

最终前沿（同会话同资源口径）：

```
fast  hierarchical      8.4ms   hit@1 0.491  hit@5 0.855
auto  routed-hier      91.5ms   hit@1 0.709  hit@5 0.836
best  hier+rerank     118.6ms   hit@1 0.709  hit@5 0.927
```

与 M1 的起点（dense 13ms/0.418 唯一快档；rerank 117ms/0.655）相比：同等延迟档位精度 +0.073 ~ +0.054，同精度档位延迟 −22%。Skill 三档位（fast/auto/best）与前沿三档一一对应。

### 发现 4（继承）：学习型路由仍不可用

十臂结果再次确认 M3 结论（AUC 0.609，hit@1 0.618 超容忍度）。在扩数据之前不再投入。

## 4. Skill 封装（课题承诺的交付形态）

`skill/adaptive-retrieval/`：

- **零配置**：`index <docs_dir>` 一条命令完成"切块（粗+细两层）→ 编码 → 落盘"，无需配置文件；
- **一个入口三种用法**：CLI（index/retrieve）、Python import（`Retriever.retrieve(query, profile)`）、SKILL.md 描述文件（可被 agent 环境直接加载）；
- **自带评测入口**的方法学已由 benchmark 框架验证，CLI eval 子命令列入 M5（需先把 benchmark 框架的语料加载泛化到任意索引目录）；
- 已在 wx 知识库端到端验证（28 粗块/121 细块，三档位检索结果抽查正确）。

## 5. 效度威胁与挂起项

1. **语料规模仍是头号威胁**（29 粗块）：所有绝对数字只在该规模下成立；需要真实领域文档扩库后全部重跑——**此项需要用户提供文档，已挂起**；
2. routed-hier 的快路径占比（31%）低于 train 选型值（44%），分布偏移对占比的影响大于对精度的影响；
3. 延迟为 GPU 独占数字，CPU 线上环境的绝对值与比例均需复测；
4. 检索自评兜底依赖 LLM API（本环境无 LLM_API_KEY），继续挂起。
