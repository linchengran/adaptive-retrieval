# M5 报告：跨域验证（DuReader 语料，37 倍规模）

> 课题：自适应检索方案与 Skill（M5 阶段：跨域压力测试）
> 日期：2026-10-07
> 数据：`experiments/m5_dureader/`（results.json / build_meta.json / testset.json）

## 1. 实验设置

| 项 | 值 |
|----|----|
| 数据源 | `zyznull/dureader-retrieval-ranking` dev 集（真实搜索引擎问答） |
| 查询 | 随机抽样 200 条（seed=42，过滤无正例行） |
| 语料 | 每条查询的正例段落 + 3 条难负例（天然干扰项），去重后 799 篇 → 1066 chunk |
| 规模 | **约为 wx 语料的 37 倍**；段落普遍短（<512 字符，多为 1 chunk） |
| 检索臂 | 8 臂（学习型路由为 wx 域训练，跨域无意义，跳过） |

## 2. 结果总表

| 检索臂 | hit@1 | hit@5 | ndcg@5 | p50 延迟 |
|--------|-------|-------|--------|---------|
| bm25 | 0.370 | 0.880 | 0.620 | 0.8 ms |
| dense | 0.485 | 0.980 | 0.731 | 4.4 ms |
| hybrid_rrf | 0.470 | 0.960 | 0.711 | 6.2 ms |
| hierarchical | 0.415 | 0.975 | 0.695 | 5.0 ms |
| dense+rerank | **0.615** | 0.985 | 0.802 | 194.0 ms |
| hybrid+rerank | **0.615** | 0.980 | 0.798 | 146.2 ms |
| hier+rerank | **0.615** | 0.985 | 0.799 | 131.0 ms |
| routed(agreement) | 0.570 | 0.980 | 0.774 | 92.8 ms（fast 48.5%） |
| routed-hier(agreement) | 0.525 | 0.975 | 0.750 | 80.6 ms（fast 49%） |

## 3. 核心发现：方法的适用边界被找到了

这正是跨域验证的价值——四个在 wx 语料上成立的结论，只有部分存活：

### 仍然成立：rerank 是最强精度杠杆

三个 rerank 臂并列 hit@1 0.615，比 dense 高 **+0.13**（wx 语料上是 +0.24→+0.22）。"重排序买精度"是跨域最稳健的结论，且三个召回路径（dense/hybrid/hier）喂给 reranker 后结果趋同——**候选质量到达一定水平后，瓶颈在 reranker 而非召回**。

### 失效 1：分层分块在短段落语料上是有害的

hierarchical 0.415 vs dense 0.485，**负收益 -0.07**。原因清楚：DuReader 段落本来就只有几百字，句级细切（120 字符）把完整的短段落进一步打碎，细块丢失上下文导致向量质量下降。**分层分块是"长文档语料"的技术，不是通用技术**——它的正确用法应该由语料统计特征（平均 chunk 长度）自动启停。

### 失效 2：混合检索不再优于纯 dense

hybrid 0.470 vs dense 0.485。wx 语料上 BM25 独占命中的"专有名词效应"在短段落通用问答上消失（bm25 本身只有 0.370，比 dense 弱得多）。混合的价值依赖于"两路各有所长"的语料条件。

### 部分成立：一致性路由的延迟收益稳健，但"零精度损失"不再成立

- 好消息：快路径占比从 29% 涨到 **48.5%**，延迟 92.8ms vs 194ms（**省 52%**），延迟侧结论跨域稳健；
- 坏消息：hit@1 0.570 vs 0.615，**损失 -0.045，超出 0.02 容忍度**。机理：agreement 信号要求两路各自够强，而此语料上 BM25 弱（0.370），"两路一致"不再是"dense 已对"的可靠证据。

### 结论修正（诚实版）

M2-M4 的"精度不掉、延迟下降"应限定为：**长文档、双路各有优势的语料**。通用短段落语料上，自适应路由的真实形态是"延迟换一点精度"（-0.045 hit@1 换 -52% 延迟），这对延迟敏感场景仍然划算，但不能再用"不掉点"作宣传语。

## 4. 方法适用边界总结（当前证据下）

| 技术 | 长文档语料（wx 型） | 短段落语料（DuReader 型） |
|------|--------------------|--------------------------|
| 分层分块 | ✅ 非重排臂最优 | ❌ 有害（-0.07） |
| 混合 RRF | ✅ hit@5 +0.15 | ⚪ 与 dense 持平 |
| rerank | ✅ +0.22 | ✅ +0.13（最稳健） |
| agreement 路由 | ✅ 零损失省 20-29% | ⚠️ 省 52% 但 -0.045 |

**由此得出 M6 的明确方向：语料感知的档位配置。** 索引时统计平均 chunk 长度等元特征，自动决定：短段落语料 → fast 档用 dense、auto 阈值收紧或改为"延迟优先"；长文档语料 → 维持现行配置。这把"自适应"从查询级扩展到了语料级，本身就是一个新的可发表点。

## 6. M6 展望

1. **语料感知配置**（最高优先级）：索引时计算元特征 → 自动选 fast 档实现与路由参数；
2. **长文档版的 DuReader**：从 `dureader-retrieval-corpus`（88M 段落全集）抽长文档构建，验证分层分块在大规模真实语料上的表现；
3. 学习型路由：在新语料上重标 train（正例充足），重训并跨域测试；
4. Skill 的 auto 档实现语料感知后，更新 SKILL.md 的边界声明。
