# M1 基线报告：检索评测框架与三路基线

> 课题：自适应检索方案与 Skill（见 [开题分析](../开题分析-自适应检索Skill.md)）
> 日期：2026-10-07
> 环境：Python 3.13，RTX 5060 GPU，transformers 5.10.2 / sentence-transformers 6.0.0

## 1. 本次交付

- **统一评测框架**（`benchmark/`）：可插拔检索器（统一 `retrieve(query, top_k)` 接口）+ chunk 级指标（Hit/Recall/MRR/nDCG@{1,3,5}，口径与小程序侧 `eval_retrieval.py` 一致）+ 延迟测量（预热后计时，p50/p95/mean）。后续每一路新检索策略只需新增一个类。
- **三路基线数字**（`experiments/m1_baseline/results.json`）。

## 2. 实验设置

| 项 | 值 |
|----|----|
| 语料 | wx 程序 server 知识库，29 个 chunk（4 份文档，recursive 切块 512 字符） |
| 测试集 | 主项目 `experiments/splits/test.json`，17 条 held-out 查询，带 chunk 级相关标注 |
| 评测指标 | chunk 级 hit@k / recall@k / mrr@k / ndcg@k，k=1,3,5 |
| 检索臂 | dense（bge-small-zh + FAISS）、bm25（jieba + BM25Okapi）、dense+rerank（bge-reranker-base 重排 top10→5） |

## 3. 基线结果

### 精度（chunk 级，17 条平均）

| 检索臂 | hit@1 | hit@3 | hit@5 | recall@5 | mrr@5 | ndcg@5 |
|--------|-------|-------|-------|----------|-------|--------|
| bm25 | 0.529 | 0.882 | 0.882 | 0.741 | 0.706 | 0.677 |
| dense | 0.647 | 0.882 | 0.941 | 0.764 | 0.770 | 0.703 |
| **dense+rerank** | **0.882** | **0.941** | **0.941** | **0.776** | **0.912** | **0.804** |

### 延迟（单查询，含全部检索计算）

| 检索臂 | p50 | p95 | 相对 dense |
|--------|-----|-----|-----------|
| bm25 | 0.23 ms | 0.39 ms | ~40x 快 |
| dense | 9.3 ms | 10.1 ms | 1x |
| dense+rerank | 121.8 ms | 131.9 ms | **13x 慢** |

### 核心观察：精度-延迟权衡已被量化

- rerank 相比纯 dense：hit@1 **+0.235**（0.647→0.882），ndcg@5 +0.102，但延迟 **13 倍**（9.3→121.8 ms）。
- 这正是开题分析的动机：**rerank 的精度收益是按查询等概率付出的延迟税**。若路由器能让一半查询免付这笔税（它们本来 dense 就排对了），平均延迟近乎减半而精度接近全量 rerank——这就是 RQ1 要验证的核心假设，M2 的路由器实验将直接针对这 17 条中 dense 已命中 rerank 才没命中的部分。
- BM25 比 dense 快 40 倍且在 3 条查询上独占命中，说明"短路径"甚至可以不只是省 rerank。

## 4. 互补性分析（混合检索的依据，RQ2）

hit@1 口径下 17 条查询的分布：

| 情形 | 条数 |
|------|------|
| dense 与 bm25 双双命中 | 6 |
| 仅 dense 命中 | 5 |
| 仅 bm25 命中 | 3 |
| 双双落空 | 3 |

- **bm25 独占命中**（dense 漏掉的）：含专有名词/英文词的查询——"需要学习 Linux 吗""更适合机器人还是 NLP""经典书籍推荐"。词面匹配抓住了向量模型丢失的实体。
- **dense 独占命中**：口语化改写类查询——"一定要读研吗"（原文说"考研"）、"就业前景怎么样"（原文是"就业方向"）。语义匹配的优势。
- 两路 RRF 融合理论上限可再修复 3 条 hit@1（0.882 → 最多 1.0 结合 rerank）；**双双落空的 3 条**（"什么是神经网络""需要什么硬件基础""毕业生就业去向"）是 M3 分层分块与查询改写的直接目标。

## 5. 环境问题记录（重要，影响后续所有实验）

运行中发现 HF 缓存 `~/.cache/huggingface/hub/models--BAAI--bge-small-zh-v1.5` 已被污染：快照里混入了 `adapter_config.json`、`preprocessor_config.json`、`processor_config.json`（应为此前 LoRA 微调实验写回缓存所致）。transformers 5.x 读取这些文件时直接报错 `Unrecognized processing class`。

处置：未动原缓存（避免影响小程序侧复现），在 `models/` 下经 hf-mirror 下载了干净副本，本课题所有实验统一使用本地副本。**建议主项目侧也排查该缓存，bge-reranker-base 可能同样受影响。**

## 6. 效度威胁（如实声明）

1. **测试集只有 17 条**：所有差异（尤其 +0.235 的 hit@1）在 n=17 下单条查询就是 0.059 的波动，当前数字只用于确立趋势与框架，不构成统计结论。M2 前应把测试集扩到 50+ 条。
2. **语料只有 29 个 chunk**：检索任务偏容易，hit@5 已达 0.94，天花板效应会压缩各臂差距；扩语料是提升实验分辨率的另一优先项。
3. 标注为单标注（自建），未做标注一致性检验。
4. 延迟测量在本机 GPU 环境，rerank 的 13 倍比例在小程序线上 CPU 环境会更大（对课题更有利）。

## 7. M2 就绪状态与下一步

框架已支持即插即用，M2 需要新增的臂：

1. `HybridRRFRetriever`：dense + bm25 RRF 融合（预期修复 3 条 bm25 独占命中）；
2. `RoutedRetriever`：规则版路由器（查询含英文实体/短查询→bm25 或短路径；其余→dense），验证"免 rerank 不掉精度"的查询占比；
3. 测试集扩充至 50+ 条、语料扩充后重建索引并重跑全部基线。
